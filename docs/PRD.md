## 目标与已确认约束

提供一套面向单团队的 RustDesk 自托管账号 API，让成员使用官方客户端登录账号，在多台电脑间同步个人通讯录，管理员能够开通与停用账号，降低小团队部署、维护和理解成本。源码按D-05公开并采用非商业许可。

已确认（E-01）：单团队、无多租户；兼容未修改的官方客户端，配置 API Server 地址接入；先比较技术栈再选型；团队共享通讯录放到第二阶段；独立开发轻量服务、参考现有兼容接口。

新增已确认（E-08）：数据库仅支持SQLite与PostgreSQL，两者均纳入首期；需要接入OIDC/OAuth 2.0统一认证。首期同时覆盖官方客户端和Web管理端的统一登录，具体身份平台尚未指定。

技术选型已确认（E-10、E-13）：后端使用Rust，按推荐采用Tokio、Axum与SQLx；依赖版本以实现锁文件为准。

身份管理目标（E-11、E-12、E-13）：统一认证用户自动创建保留首期；无匹配时默认拒绝，允许显式配置普通成员兜底。按推荐实现的单claim静态精确角色映射已通过M0，纳入首期基线；复杂映射后移。生产IdP的claim路径与角色对应值后续按实际平台配置。

发布方式确认（E-20，2026-11-04/05）：用户要求公开GitHub仓库，采用免费PR自动审查并保留人工合并，项目许可禁止商用。自有内容采用PolyForm Noncommercial 1.0.0，属于源码可用许可，不是OSI开源许可；第三方保留原许可。对外托管服务、公共镜像和版本发布另行安排，不因源码公开自动纳入首期。

新增确认（E-17）：连接凭据跨设备同步、设备归属和“我的设备”沿用官方客户端协议。用户已取消按用户、用户组限制远控。E-18追加确认：采用固定PR #734解决登录后的hbbs握手兼容，保留hbbr；不增加远控ACL，见[兼容记录](rendezvous-compatibility.md)。具体契约见[设备与凭据设计](device-credentials-design.md)。

## 用户与关键场景

| 角色 | 场景 | 期望结果 |
|---|---|---|
| 部署管理员 | 首次部署，配置域名、HTTPS与数据卷 | 安全建立首个管理员，获得明确的客户端接入说明 |
| 账号管理员 | 开通成员账号、重置密码、停用离职账号 | 成员可登录；停用后其API会话不可继续访问 |
| 普通成员 | 在电脑A登录，维护联系人、别名与标签，在电脑B登录 | 能读取同一账号最近成功保存的个人通讯录 |
| 普通成员 | 忘记账号密码或更换密码 | 有明确的管理重置和Web自助改密路径 |
| 统一认证用户 | 从官方客户端或Web管理端进入统一登录 | 在身份平台认证后回到本服务，访问本人通讯录；不向本服务提交身份平台密码 |
| 身份管理员 | 在统一身份平台维护用户与角色/用户组 | 本服务自动建档；启用映射后，后续登录反映角色升降级，无需重复人工维护 |
| 部署维护者 | 首次部署、升级和恢复 | 按文档重现部署，数据可备份恢复，了解支持范围 |

账号密码与远控密码是不同概念；账号停用针对本API的数据访问。远控建立连接仍受信令、中继和被控客户端机制影响，首期不承诺账号停用能断开远控或阻止所有新远控连接。

## 关键用户流程

1. 部署者完成HTTPS和持久化配置 → 使用一次性引导凭据或本地初始化命令建立管理员 → 禁用重复初始化入口。
2. 管理员创建成员账号 → 成员取得初始凭据 → 在官方客户端配置ID Server、Key及API Server → 登录 → 显示本人信息。
3. 成员在A修改个人通讯录 → 服务端成功提交 → B刷新后得到已提交内容；网络失败明确报错，不把失败数据当成已同步。
4. 本地成员在Web修改密码，或管理员重置本地密码/停用任意来源账号 → 服务端撤销对应会话 → 旧token再次调用API被拒绝；需要重新登录。
5. 管理员备份 → 在干净环境恢复 → 用户、通讯录、必要会话状态与审计数据符合已定义的恢复策略。
6. 成员选择统一登录 → 浏览器进入IdP完成认证 → 本服务校验身份、准入和本地停用状态，按当前策略确定角色 → 按issuer+sub查找或自动创建用户及个人簿 → 签发本服务会话 → 官方客户端或Web管理端完成登录。启用映射时校验配置的角色声明。
7. 用户再次通过OIDC认证 → 重新检查准入，启用映射时重新计算角色 → 更新已有用户权限；角色下降或失去准入时撤销已有会话，不删除个人通讯录。IdP侧变化尚未被本服务观察到时，不声称已经同步。

不假设官方客户端提供“首次登录必须改密”界面。若需要强制首改，必须补充Web完成引导和客户端拒绝登录时的清晰提示，待另行确认。

## 非功能目标与产品限制

以下为待讨论的验收负载假设，不是实测承诺：100个账号、200个同时有效的登录客户端、每用户1000个通讯录条目，单实例部署。有效登录数不等于HTTP并发；不以远控并发数作为本API容量指标。实际规模确认后再制定测试硬件、请求组合、吞吐、P95和错误率门槛。

P0支持SQLite与PostgreSQL，可由部署者选择；SQLite建议用于轻量单实例部署，PostgreSQL用于已有PG基础设施或更高写入需求。首期两种数据库均须验收，不要求Redis，不支持MySQL。服务应明确处理无效JSON、请求体超限、数据库不可写和IdP不可用等上游请求失败，不返回误导性成功。配置、token、日志留存和备份策略应文档化。

统一认证使用OIDC身份层和OAuth 2.0授权码流程，不将任意OAuth access token直接当作本服务登录凭据。用户自动创建和简版角色映射保留首期，复杂规则后移。无匹配默认拒绝、可显式配置普通成员兜底，不提供管理员兜底。简版映射只支持admin/member、一个可信claim、静态精确匹配及固定admin优先；不含正则、表达式、多claim组合或Web规则编辑器。生产平台的具体值见D-10。

OIDC角色无匹配时默认拒绝；显式开启member兜底后，该IdP中通过认证、未被本地停用且角色未匹配的用户也可进入并自动建档为member。缺失或合法空角色声明按无匹配处理，类型错误拒绝；认证与协议错误不能触发兜底。上述行为已有M0配置说明和验收记录。

每次OIDC身份验证完成后同步角色；降权撤销旧会话，后续API读取当前准入和角色。IdP角色删除/停用若尚未发生后续认证，本服务不会自动感知；事件推送、完整目录同步及全局单点登出不属于P0保证。准入或映射配置变更由单实例重启应用，新策略接受请求前使所有OIDC会话与未完成登录尝试失效。本地账号与OIDC并存，成员可使用管理员创建的本地账号；本地应急管理员独立保留，不受外部映射规则影响，OIDC用户不生成本地密码。

Legacy通讯录为整本快照，建议首期“最后一次成功提交生效”；服务端不能凭空恢复客户端未提交或被旧快照覆盖的修改。多人共享和冲突合并不包含在首期承诺中。

无Bearer的sysinfo/heartbeat不能用于归属。本轮只采用通过认证的登录关联；不接收匿名上报来改名、夺取归属或授权远控。归属只控制目录与管理数据，不影响既有远控权限。

## 风险与本轮验证状态

- 官方账号API没有本项目可直接采用的稳定契约承诺；需固定版本并维护兼容用例。
- 账号权限与远控连接授权的执行链不同；首期只保证API范围内权限，用户已明确不做强制远控ACL。
- 社区API存在需改造的会话和权限细节，源码已拉取不等于选定或安全验收通过。
- 历史M0实现最小服务、通过10项Rust测试与Clippy，并在SQLite及PostgreSQL16.15上各通过15项真实Keycloak HTTP端到端用例；macOS官方1.5.0的本地登录、OIDC、个人簿读写和退出实机验证通过。测试会话均已撤销，用户确认恢复原API地址，测试服务已停止；未上线部署。
- 用户已要求按推荐方案进入验证；生产平台、完整支持矩阵和后续范围按实际验收收敛，不能把M0自动化结果等同于完整P0交付。
- M1已通过启用PG的19项Rust测试、前端4项测试/类型检查/构建、双库40项M1 HTTP用例及30项M0回归，并完成6项实际浏览器检查。M1结果不扩大原M0实机支持矩阵。本轮M2/M3后续结果与M1历史构建分开记录。
